## SC-01: 신규 회원가입

**시나리오 ID**: SC-01
**시나리오명**: 신규 사용자 회원가입
**관련 UC-ID**: UC-01
**액터**: 비인증 사용자 (신규 방문자)

### 사전 조건 (Precondition)

- 사용자가 TodoListApp에 계정이 없는 상태이다.
- 사용자가 PC 또는 모바일 웹 브라우저로 서비스에 접속한 상태이다.

### 기본 흐름 (Basic Flow)

1. 사용자가 서비스 메인 화면에서 "회원가입" 버튼을 클릭한다.
2. 시스템이 회원가입 폼(이름, 이메일, 비밀번호 입력 필드)을 표시한다.
3. 사용자가 이름을 입력한다. (예: "김철수")
4. 사용자가 이메일 주소를 입력한다. (예: "chulsoo@example.com")
5. 사용자가 비밀번호를 입력한다. (예: "Pass1234")
6. 사용자가 "가입하기" 버튼을 클릭한다.
7. 시스템이 입력값 유효성을 검증한다.
8. 시스템이 이메일 중복 여부를 확인한다.
9. 시스템이 비밀번호를 bcrypt로 암호화하여 저장한다.
10. 시스템이 기본 카테고리(일반, 업무, 개인)를 해당 사용자에게 자동 부여한다.
11. 시스템이 가입 완료 메시지를 표시하고 로그인 화면으로 이동한다.

### 대안 흐름 / 예외 흐름 (Alternative / Exception Flow)

- **[E-01] 이메일 형식 오류**: 사용자가 RFC 5322 형식에 맞지 않는 이메일을 입력한 경우, 시스템이 "올바른 이메일 형식을 입력해 주세요." 메시지를 표시하고 가입을 중단한다.
- **[E-02] 이메일 중복**: 이미 가입된 이메일 주소를 입력한 경우, 시스템이 "이미 사용 중인 이메일입니다." 메시지를 표시하고 가입을 중단한다.
- **[E-03] 비밀번호 규칙 미충족**: 비밀번호가 8자 미만이거나 영문자·숫자가 각 1자 이상 포함되지 않은 경우, 시스템이 "비밀번호는 8자 이상, 영문자와 숫자를 각 1자 이상 포함해야 합니다." 메시지를 표시한다.
- **[E-04] 이름 누락 또는 초과**: 이름이 입력되지 않았거나 50자를 초과한 경우, 시스템이 해당 필드에 오류 메시지를 표시한다.
- **[E-05] 이메일 최대 길이 초과**: 이메일이 255자를 초과한 경우, 시스템이 입력을 차단하거나 오류 메시지를 표시한다.
- **[E-06] 비밀번호 최대 길이 초과**: 비밀번호가 64자를 초과한 경우, 시스템이 오류 메시지를 표시한다.

### 사후 조건 (Postcondition)

- 새로운 사용자 계정이 시스템에 저장된다.
- 비밀번호는 bcrypt로 암호화된 상태로 저장된다.
- 사용자는 로그인 화면으로 이동된다.

## SC-02: 로그인 및 로그아웃

**시나리오 ID**: SC-02
**시나리오명**: 사용자 로그인 후 서비스 이용 및 로그아웃
**관련 UC-ID**: UC-02, UC-03
**액터**: 가입된 사용자 (비인증 상태)

### 사전 조건 (Precondition)

- 사용자가 이미 회원가입을 완료한 상태이다.
- 사용자가 로그아웃 상태로 서비스에 접속한 상태이다.

### 기본 흐름 (Basic Flow)

1. 사용자가 로그인 화면에서 이메일과 비밀번호를 입력한다.
2. 사용자가 "로그인" 버튼을 클릭한다.
3. 시스템이 이메일과 비밀번호의 일치 여부를 검증한다.
4. 시스템이 JWT Access Token(유효기간 1시간)과 Refresh Token(유효기간 7일)을 발급한다.
5. 시스템이 Access Token과 Refresh Token을 클라이언트 Zustand 메모리에 저장한다.
6. 시스템이 사용자를 할일 목록 메인 화면으로 이동시킨다.
7. 사용자가 서비스를 이용한다.
8. 사용자가 상단 메뉴의 "로그아웃" 버튼을 클릭한다.
9. 시스템이 클라이언트 측의 Access Token 및 Refresh Token을 제거한다.
10. 시스템이 사용자를 로그인 화면으로 이동시킨다.

### 대안 흐름 / 예외 흐름 (Alternative / Exception Flow)

- **[E-01] 이메일 또는 비밀번호 불일치**: 입력한 이메일이 존재하지 않거나 비밀번호가 틀린 경우, 시스템이 "이메일 또는 비밀번호가 올바르지 않습니다." 메시지를 표시하고 로그인을 거부한다.
- **[E-02] Access Token 만료**: 로그인 후 1시간이 경과하여 Access Token이 만료된 경우, 시스템이 Refresh Token을 사용하여 Access Token을 자동 갱신한다.
- **[E-03] Refresh Token 만료**: Refresh Token(7일)도 만료된 경우, 시스템이 "세션이 만료되었습니다. 다시 로그인해 주세요." 메시지를 표시하고 로그인 화면으로 이동시킨다.
- **[E-04] 필드 미입력**: 이메일 또는 비밀번호를 입력하지 않고 로그인을 시도한 경우, 시스템이 해당 필드에 오류 메시지를 표시한다.

### 사후 조건 (Postcondition)

- (로그인 완료 시) 사용자가 인증된 상태로 서비스를 이용할 수 있다.
- (로그아웃 완료 시) 클라이언트에 저장된 모든 인증 토큰이 제거되고 비인증 상태로 전환된다.

## SC-03: 개인 정보 수정

**시나리오 ID**: SC-03
**시나리오명**: 로그인 사용자의 이름 및 비밀번호 수정
**관련 UC-ID**: UC-04
**액터**: 인증된 사용자

### 사전 조건 (Precondition)

- 사용자가 로그인된 상태이다.
- 사용자가 프로필/개인정보 수정 화면에 접근한 상태이다.

### 기본 흐름 (Basic Flow)

1. 사용자가 상단 메뉴 또는 프로필 영역에서 "개인정보 수정" 메뉴를 선택한다.
2. 시스템이 현재 이름이 표시된 개인정보 수정 폼을 보여준다.
3. 사용자가 변경할 이름을 수정한다. (예: "김철수" → "김영수")
4. 사용자가 비밀번호를 변경하려는 경우, 현재 비밀번호와 새 비밀번호를 입력한다.
5. 사용자가 "저장" 버튼을 클릭한다.
6. 시스템이 입력값 유효성을 검증한다.
7. 비밀번호 변경 요청이 있는 경우, 시스템이 현재 비밀번호 일치 여부를 확인한다.
8. 시스템이 변경 사항을 저장하고 "수정이 완료되었습니다." 메시지를 표시한다.

### 대안 흐름 / 예외 흐름 (Alternative / Exception Flow)

- **[A-01] 이름만 수정하는 경우**: 비밀번호 변경 필드를 비워두고 저장하면, 시스템이 이름만 업데이트한다. (비밀번호 변경은 선택 사항)
- **[E-01] 현재 비밀번호 불일치**: 비밀번호 변경 시 입력한 현재 비밀번호가 일치하지 않는 경우, 시스템이 "현재 비밀번호가 올바르지 않습니다." 메시지를 표시하고 저장을 중단한다.
- **[E-02] 새 비밀번호 규칙 미충족**: 새 비밀번호가 최소 8자, 영문자·숫자 각 1자 이상 조건을 만족하지 않는 경우, 시스템이 오류 메시지를 표시한다.
- **[E-03] 이름 유효성 오류**: 이름이 빈 값이거나 50자를 초과하는 경우, 시스템이 오류 메시지를 표시하고 저장을 중단한다.
- **[E-04] 인증 만료**: 작업 중 Access Token이 만료된 경우, 시스템이 Refresh Token으로 자동 갱신을 시도하고, 실패 시 로그인 화면으로 이동시킨다.

### 사후 조건 (Postcondition)

- 변경된 이름이 시스템에 반영된다.
- 비밀번호 변경 요청이 있었던 경우, 새 비밀번호가 bcrypt로 암호화되어 저장된다.

## SC-04: 회원 탈퇴

**시나리오 ID**: SC-04
**시나리오명**: 사용자의 계정 삭제 및 회원 탈퇴
**관련 UC-ID**: UC-14
**액터**: 인증된 사용자

### 사전 조건 (Precondition)

- 사용자가 로그인된 상태이다.
- 사용자가 탈퇴를 원하며, 데이터 삭제에 동의할 준비가 된 상태이다.

### 기본 흐름 (Basic Flow)

1. 사용자가 개인정보 수정 화면 또는 설정 메뉴에서 "회원 탈퇴" 버튼을 클릭한다.
2. 시스템이 탈퇴 확인 경고 메시지를 표시한다. ("탈퇴 시 모든 데이터(카테고리, 할일)가 즉시 삭제되며 복구할 수 없습니다.")
3. 사용자가 본인 확인을 위해 현재 비밀번호를 입력한다.
4. 사용자가 "탈퇴 확인" 버튼을 클릭한다.
5. 시스템이 입력한 비밀번호의 일치 여부를 검증한다.
6. 시스템이 해당 사용자의 할일(Todo) 전체를 삭제한다.
7. 시스템이 해당 사용자의 사용자 정의 카테고리 전체를 삭제한다.
8. 시스템이 해당 사용자 계정(User)을 삭제한다.
9. 시스템이 클라이언트 측 토큰을 제거하고 "탈퇴가 완료되었습니다." 메시지를 표시한 후 메인 화면으로 이동시킨다.

### 대안 흐름 / 예외 흐름 (Alternative / Exception Flow)

- **[A-01] 탈퇴 취소**: 경고 메시지에서 사용자가 "취소" 버튼을 클릭하면, 탈퇴 절차가 중단되고 이전 화면으로 돌아간다.
- **[E-01] 비밀번호 불일치**: 입력한 비밀번호가 현재 비밀번호와 일치하지 않는 경우, 시스템이 "비밀번호가 올바르지 않습니다." 메시지를 표시하고 탈퇴를 중단한다.
- **[E-02] 비밀번호 미입력**: 비밀번호를 입력하지 않고 탈퇴를 시도한 경우, 시스템이 "비밀번호를 입력해 주세요." 메시지를 표시한다.

### 사후 조건 (Postcondition)

- 해당 사용자 계정, 사용자 정의 카테고리, 모든 할일 데이터가 시스템에서 즉시 삭제된다.
- 기본 카테고리(시스템 공통)는 삭제되지 않는다.
- 사용자는 더 이상 해당 계정으로 로그인할 수 없다.

## SC-05: 사용자 정의 카테고리 등록 후 할일 등록

**시나리오 ID**: SC-05
**시나리오명**: 새 카테고리를 생성하고 해당 카테고리로 할일 등록
**관련 UC-ID**: UC-05, UC-08
**액터**: 인증된 사용자

### 사전 조건 (Precondition)

- 사용자가 로그인된 상태이다.
- 시스템 기본 카테고리(일반, 업무, 개인)가 존재한다.
- 사용자가 새로운 분류 항목이 필요하다고 판단한 상태이다. (예: "운동" 카테고리가 없음)

### 기본 흐름 (Basic Flow)

1. 사용자가 카테고리 관리 화면으로 이동한다.
2. 사용자가 "카테고리 추가" 버튼을 클릭한다.
3. 시스템이 카테고리명 입력 폼을 표시한다.
4. 사용자가 카테고리명을 입력한다. (예: "운동")
5. 사용자가 "저장" 버튼을 클릭한다.
6. 시스템이 입력값 유효성을 검증한다. (필수, 최소 1자, 최대 30자, 동일 사용자 내 중복 불가)
7. 시스템이 새 카테고리를 사용자 소유로 저장하고 카테고리 목록에 추가한다.
8. 사용자가 할일 목록 화면으로 이동하여 "할일 추가" 버튼을 클릭한다.
9. 시스템이 할일 등록 폼을 표시한다. (제목, 카테고리 선택, 설명, 종료예정일)
10. 사용자가 제목을 입력한다. (예: "헬스장 등록하기")
11. 사용자가 카테고리 드롭다운에서 방금 생성한 "운동"을 선택한다.
12. 사용자가 설명을 입력한다. (예: "집 근처 헬스장 알아보기") — 선택사항
13. 사용자가 종료예정일을 선택한다. (예: 2026-05-20) — 선택사항
14. 사용자가 "등록" 버튼을 클릭한다.
15. 시스템이 입력값 유효성을 검증한다.
16. 시스템이 할일을 저장하고 할일 목록에 추가한다.
17. 사용자가 새로 등록된 할일을 목록에서 확인한다.

### 대안 흐름 / 예외 흐름 (Alternative / Exception Flow)

- **[A-01] 기본 카테고리로 할일 등록**: 새 카테고리를 생성하지 않고 기존 기본 카테고리(예: "업무")를 선택하여 할일을 등록할 수 있다. (8단계부터 진행)
- **[E-01] 카테고리명 중복**: 동일 사용자가 이미 동일한 이름의 카테고리를 보유한 경우, 시스템이 "이미 존재하는 카테고리명입니다." 메시지를 표시하고 저장을 중단한다.
- **[E-02] 카테고리명 길이 초과**: 카테고리명이 30자를 초과하는 경우, 시스템이 오류 메시지를 표시한다.
- **[E-03] 할일 제목 누락**: 할일 제목을 입력하지 않고 등록을 시도한 경우, 시스템이 "제목을 입력해 주세요." 메시지를 표시하고 등록을 중단한다.
- **[E-04] 할일 제목 길이 초과**: 할일 제목이 100자를 초과하는 경우, 시스템이 오류 메시지를 표시한다.
- **[E-05] 설명 길이 초과**: 설명이 1,000자를 초과하는 경우, 시스템이 오류 메시지를 표시한다.
- **[E-06] 종료예정일 과거 날짜 입력**: 종료예정일로 오늘 이전 날짜를 선택한 경우, 시스템이 "종료예정일은 오늘 이후 날짜로 설정해 주세요." 메시지를 표시하고 등록을 중단한다.
- **[E-07] 카테고리 미선택**: 카테고리를 선택하지 않고 등록을 시도한 경우, 시스템이 "카테고리를 선택해 주세요." 메시지를 표시한다.
- **[E-08] 타인 카테고리 선택 시도**: API 레벨에서 타인 소유의 카테고리를 카테고리 ID로 직접 요청하는 경우, 시스템이 접근을 거부하고 오류를 반환한다.

### 사후 조건 (Postcondition)

- 새 사용자 정의 카테고리가 해당 사용자 소유로 시스템에 저장된다.
- 새 할일이 해당 카테고리에 속한 상태로 등록된다.
- 할일의 완료 여부는 기본값 "미완료"로 설정된다.
- 할일 목록은 등록일시 내림차순으로 정렬되어 표시된다.

## SC-06: 카테고리 수정

**시나리오 ID**: SC-06
**시나리오명**: 사용자 정의 카테고리명 수정
**관련 UC-ID**: UC-06
**액터**: 인증된 사용자

### 사전 조건 (Precondition)

- 사용자가 로그인된 상태이다.
- 수정 대상인 사용자 정의 카테고리가 이미 존재한다. (예: "운동")
- 수정 대상 카테고리는 해당 사용자 소유이다.

### 기본 흐름 (Basic Flow)

1. 사용자가 카테고리 관리 화면으로 이동한다.
2. 사용자가 수정하려는 카테고리(예: "운동") 옆의 "수정" 아이콘 또는 버튼을 클릭한다.
3. 시스템이 현재 카테고리명이 입력된 수정 폼을 표시한다.
4. 사용자가 카테고리명을 변경한다. (예: "운동" → "헬스")
5. 사용자가 "저장" 버튼을 클릭한다.
6. 시스템이 입력값 유효성을 검증한다.
7. 시스템이 카테고리명을 업데이트하고 "수정이 완료되었습니다." 메시지를 표시한다.

### 대안 흐름 / 예외 흐름 (Alternative / Exception Flow)

- **[A-01] 수정 취소**: 사용자가 "취소" 버튼을 클릭하면 변경 없이 이전 화면으로 돌아간다.
- **[E-01] 기본 카테고리 수정 시도**: 사용자가 기본 카테고리(일반, 업무, 개인)의 수정 버튼에 접근하는 경우, 시스템이 수정 버튼을 비활성화하거나 "기본 카테고리는 수정할 수 없습니다." 메시지를 표시한다.
- **[E-02] 카테고리명 중복**: 변경하려는 이름이 동일 사용자의 다른 카테고리명과 중복되는 경우, 시스템이 "이미 존재하는 카테고리명입니다." 메시지를 표시하고 저장을 중단한다.
- **[E-03] 카테고리명 빈 값 또는 길이 초과**: 카테고리명이 비어있거나 30자를 초과하는 경우, 시스템이 오류 메시지를 표시한다.

### 사후 조건 (Postcondition)

- 수정된 카테고리명이 시스템에 반영된다.
- 해당 카테고리에 속한 기존 할일들은 수정된 카테고리명 하에 그대로 유지된다.

## SC-07: 카테고리 삭제

**시나리오 ID**: SC-07
**시나리오명**: 사용자 정의 카테고리 삭제 및 할일 자동 이동
**관련 UC-ID**: UC-07
**액터**: 인증된 사용자

### 사전 조건 (Precondition)

- 사용자가 로그인된 상태이다.
- 삭제 대상인 사용자 정의 카테고리가 이미 존재한다. (예: "헬스")
- 해당 카테고리는 해당 사용자 소유이다.

### 기본 흐름 (Basic Flow)

1. 사용자가 카테고리 관리 화면으로 이동한다.
2. 사용자가 삭제하려는 카테고리(예: "헬스") 옆의 "삭제" 아이콘 또는 버튼을 클릭한다.
3. 시스템이 삭제 확인 메시지를 표시한다. ("해당 카테고리에 속한 할일이 X건 있습니다. 삭제 시 해당 할일은 '일반' 카테고리로 이동됩니다. 계속하시겠습니까?")
4. 사용자가 "확인" 버튼을 클릭한다.
5. 시스템이 해당 카테고리에 속한 할일들을 기본 카테고리 "일반"으로 자동 이동시킨다.
6. 시스템이 해당 카테고리를 삭제한다.
7. 시스템이 "카테고리가 삭제되었으며, 소속 할일은 '일반' 카테고리로 이동되었습니다." 안내 메시지를 표시한다.

### 대안 흐름 / 예외 흐름 (Alternative / Exception Flow)

- **[A-01] 카테고리에 할일 없는 경우**: 삭제 대상 카테고리에 속한 할일이 없는 경우, 시스템이 단순 삭제 확인 메시지("이 카테고리를 삭제하시겠습니까?")를 표시한 후 삭제를 진행한다. 할일 이동 안내는 생략한다.
- **[A-02] 삭제 취소**: 사용자가 확인 메시지에서 "취소" 버튼을 클릭하면, 카테고리 및 할일은 변경 없이 유지된다.
- **[E-01] 기본 카테고리 삭제 시도**: 사용자가 기본 카테고리(일반, 업무, 개인)를 삭제하려는 경우, 시스템이 삭제 버튼을 비활성화하거나 "기본 카테고리는 삭제할 수 없습니다." 메시지를 표시하고 삭제를 거부한다.

### 사후 조건 (Postcondition)

- 삭제된 카테고리는 시스템에서 제거된다.
- 삭제된 카테고리에 속했던 할일들은 기본 카테고리 "일반"으로 소속이 변경된다.
- 할일의 내용(제목, 설명, 종료예정일, 완료 여부)은 변경되지 않는다.

## SC-08: 할일 수정 및 완료 처리

**시나리오 ID**: SC-08
**시나리오명**: 기존 할일 내용 수정 및 완료 상태 토글
**관련 UC-ID**: UC-09, UC-11
**액터**: 인증된 사용자 (할일 소유자)

### 사전 조건 (Precondition)

- 사용자가 로그인된 상태이다.
- 수정 또는 완료 처리할 할일이 해당 사용자 소유로 등록되어 있다.
- 해당 할일의 현재 완료 여부는 "미완료" 상태이다.

### 기본 흐름 (Basic Flow)

1. 사용자가 할일 목록 화면에서 수정하려는 할일을 찾는다.
2. 사용자가 해당 할일의 "수정" 버튼 또는 아이콘을 클릭한다.
3. 시스템이 현재 할일 정보(제목, 설명, 카테고리, 종료예정일)가 채워진 수정 폼을 표시한다.
4. 사용자가 제목을 수정한다. (예: "헬스장 등록하기" → "헬스장 PT 등록하기")
5. 사용자가 종료예정일을 변경한다. (예: 2026-05-20 → 2026-05-25)
6. 사용자가 "저장" 버튼을 클릭한다.
7. 시스템이 입력값 유효성을 검증하고, 소유권을 확인한다.
8. 시스템이 변경 사항을 저장하고 "수정이 완료되었습니다." 메시지를 표시한다.
9. 사용자가 할일 목록으로 돌아가 해당 할일의 완료 체크박스 또는 완료 버튼을 클릭한다.
10. 시스템이 해당 할일의 완료 여부를 "미완료 → 완료"로 변경한다.
11. 시스템이 변경된 상태를 목록에 즉시 반영한다.

### 대안 흐름 / 예외 흐름 (Alternative / Exception Flow)

- **[A-01] 완료 → 미완료 토글**: 이미 완료 상태인 할일의 완료 버튼을 클릭하면, 시스템이 "완료 → 미완료"로 상태를 되돌린다. (완료 여부 토글은 양방향 지원)
- **[A-02] 카테고리만 변경**: 수정 폼에서 제목, 설명, 종료예정일은 그대로 두고 카테고리만 변경하여 저장할 수 있다.
- **[E-01] 수정 권한 없음**: API 레벨에서 타인 소유의 할일을 수정하려는 경우, 시스템이 접근을 거부하고 오류를 반환한다.
- **[E-02] 제목 누락**: 수정 중 제목을 삭제하고 저장을 시도한 경우, 시스템이 "제목을 입력해 주세요." 메시지를 표시하고 저장을 중단한다.
- **[E-03] 제목 길이 초과**: 수정된 제목이 100자를 초과하는 경우, 시스템이 오류 메시지를 표시한다.
- **[E-04] 설명 길이 초과**: 수정된 설명이 1,000자를 초과하는 경우, 시스템이 오류 메시지를 표시한다.
- **[E-05] 종료예정일 과거 날짜**: 수정 시 종료예정일로 오늘 이전 날짜를 입력한 경우, 시스템이 오류 메시지를 표시하고 저장을 중단한다.

### 사후 조건 (Postcondition)

- 수정된 할일 정보가 시스템에 반영된다.
- 완료 처리된 할일의 완료 여부가 "완료" 상태로 저장된다.
- 할일 목록에 변경된 상태가 즉시 반영된다.

## SC-10: 할일 목록 조회 및 필터링

**시나리오 ID**: SC-10
**시나리오명**: 필터 조건을 적용하여 할일 목록 조회
**관련 UC-ID**: UC-12
**액터**: 인증된 사용자

### 사전 조건 (Precondition)

- 사용자가 로그인된 상태이다.
- 사용자가 등록한 할일이 1건 이상 존재한다.

### 기본 흐름 (Basic Flow)

1. 사용자가 할일 목록 메인 화면으로 이동한다.
2. 시스템이 해당 사용자의 모든 할일을 등록일시 내림차순으로 정렬하여 표시한다.
3. 사용자가 카테고리 필터를 적용한다. (예: "업무" 카테고리만 보기)
4. 시스템이 "업무" 카테고리에 속한 할일만 필터링하여 목록을 갱신한다.
5. 사용자가 추가로 완료 여부 필터를 적용한다. (예: "미완료"만 보기)
6. 시스템이 "업무" 카테고리 + "미완료" 조건에 부합하는 할일만 표시한다.
7. 사용자가 종료예정일 기간 필터를 적용한다. (예: 2026-05-13 ~ 2026-05-31)
8. 시스템이 세 가지 필터 조건을 모두 적용한 결과를 등록일시 내림차순으로 표시한다.

### 대안 흐름 / 예외 흐름 (Alternative / Exception Flow)

- **[A-01] 필터 초기화**: 사용자가 "필터 초기화" 버튼을 클릭하면, 시스템이 모든 필터를 제거하고 전체 할일을 등록일시 내림차순으로 다시 표시한다.
- **[A-02] 단일 필터 적용**: 카테고리, 종료예정일 기간, 완료 여부 중 하나의 조건만 선택적으로 적용할 수 있다.
- **[E-01] 조회 결과 없음**: 적용한 필터 조건에 해당하는 할일이 없는 경우, 시스템이 "조건에 맞는 할일이 없습니다." 메시지를 표시한다.
- **[E-02] 인증 만료**: 조회 중 세션이 만료된 경우, 시스템이 재인증을 요청한다.

### 사후 조건 (Postcondition)

- 사용자가 선택한 필터 조건에 맞는 할일 목록이 화면에 표시된다.
- 목록은 등록일시 내림차순으로 정렬된다.
- 사용자의 할일 데이터는 변경되지 않는다.

## SC-11: 할일 상세 조회

**시나리오 ID**: SC-11
**시나리오명**: 특정 할일의 전체 정보 상세 조회
**관련 UC-ID**: UC-13
**액터**: 인증된 사용자 (할일 소유자)

### 사전 조건 (Precondition)

- 사용자가 로그인된 상태이다.
- 상세 조회할 할일이 해당 사용자 소유로 존재한다.

### 기본 흐름 (Basic Flow)

1. 사용자가 할일 목록 화면에서 상세 정보를 확인하고 싶은 할일을 클릭하거나 "상세 보기" 버튼을 클릭한다.
2. 시스템이 소유권을 확인한다.
3. 시스템이 해당 할일의 전체 정보를 표시한다.
   - 제목
   - 설명 (입력된 경우)
   - 카테고리명
   - 종료예정일 (설정된 경우)
   - 완료 여부
   - 등록일시
   - 최종 수정일시
4. 사용자가 상세 화면에서 내용을 확인한다.
5. 사용자가 "목록으로 돌아가기" 버튼 또는 뒤로 가기를 통해 목록 화면으로 이동한다.

### 대안 흐름 / 예외 흐름 (Alternative / Exception Flow)

- **[A-01] 상세 화면에서 바로 수정**: 상세 화면에서 "수정" 버튼을 클릭하여 SC-08의 할일 수정 흐름으로 바로 진입할 수 있다.
- **[A-02] 상세 화면에서 바로 완료 처리**: 상세 화면에서 완료 체크박스 또는 완료 버튼을 클릭하여 SC-08의 완료 처리 흐름을 바로 실행할 수 있다.
- **[A-03] 상세 화면에서 바로 삭제**: 상세 화면에서 "삭제" 버튼을 클릭하여 SC-09의 할일 삭제 흐름으로 바로 진입할 수 있다.
- **[E-01] 조회 권한 없음**: API 레벨에서 타인 소유의 할일 ID로 직접 상세 조회를 시도하는 경우, 시스템이 접근을 거부하고 오류를 반환한다.
- **[E-02] 존재하지 않는 할일**: 이미 삭제된 할일의 상세 페이지에 접근하는 경우, 시스템이 "존재하지 않는 할일입니다." 메시지를 표시하고 목록으로 이동시킨다.

### 사후 조건 (Postcondition)

- 사용자가 해당 할일의 전체 정보를 확인한다.
- 조회 과정에서 할일 데이터는 변경되지 않는다.
