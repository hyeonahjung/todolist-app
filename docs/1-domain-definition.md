# 도메인 정의서 - TodoListApp

**버전**: 1.0
**작성일**: 2026-05-12
**작성자**: Business Analyst

---

## 1. 프로젝트 개요

### 목적

인증된 사용자가 자신만의 할일을 카테고리별로 등록, 관리, 조회할 수 있는 개인 할일 관리 애플리케이션을 제공한다.

### 배경

- 개인별 할일을 체계적으로 관리할 수 있는 전용 도구의 부재
- 사용자 인증 기반으로 데이터를 분리하여 안전하게 저장하는 환경의 필요
- 카테고리 단위의 할일 분류 및 다양한 조건 필터링 기능의 요구

---

## 2. 핵심 도메인 개념

| 용어 | 정의 |
|------|------|
| **사용자 (User)** | 회원가입 후 인증을 통해 앱을 사용하는 주체 |
| **할일 (Todo)** | 사용자가 등록한 단위 작업 항목 |
| **카테고리 (Category)** | 할일을 분류하는 그룹 단위. 기본 카테고리와 사용자 정의 카테고리로 구분됨 |
| **기본 카테고리** | 시스템이 제공하는 공통 카테고리 (예: 일반, 업무, 개인 등) |
| **사용자 정의 카테고리** | 인증된 사용자가 직접 생성한 카테고리 |
| **종료예정일 (Due Date)** | 할일을 완료해야 하는 목표 날짜 |
| **완료 여부 (Completion Status)** | 할일의 진행 상태 (완료 / 미완료) |

## 3. 도메인 모델

### 주요 엔티티

#### User (사용자)
- `user_id` : 고유 식별자
- `email` : 이메일 (로그인 ID)
- `password` : 암호화된 비밀번호
- `name` : 이름
- `created_at` : 가입일시

#### Category (카테고리)
- `category_id` : 고유 식별자
- `name` : 카테고리명
- `is_default` : 기본 카테고리 여부
- `user_id` : 소유 사용자 (기본 카테고리는 null)

#### Todo (할일)
- `todo_id` : 고유 식별자
- `user_id` : 소유 사용자
- `category_id` : 분류 카테고리
- `title` : 할일 제목
- `description` : 설명
- `due_date` : 종료예정일
- `is_completed` : 완료 여부
- `created_at` : 등록일시

### 엔티티 관계

```
User ──< Todo >── Category
  └──────────────< Category (사용자 정의)
```

- User : Todo = 1 : N (사용자 한 명이 여러 할일 보유)
- User : Category = 1 : N (사용자 한 명이 여러 사용자 정의 카테고리 생성)
- Category : Todo = 1 : N (하나의 카테고리에 여러 할일 포함)

## 4. 핵심 비즈니스 규칙

| 번호 | 규칙 |
|------|------|
| BR-01 | 사용자는 회원가입 후 로그인 인증을 완료해야 서비스를 이용할 수 있다. |
| BR-02 | 할일은 반드시 인증된 사용자 소유로 저장되며, 타 사용자의 할일에 접근할 수 없다. |
| BR-03 | 할일 등록 시 카테고리는 필수 지정 항목이며, 기본 카테고리 또는 사용자 정의 카테고리 중 하나를 선택해야 한다. |
| BR-04 | 기본 카테고리는 시스템이 제공하며 사용자가 삭제하거나 수정할 수 없다. |
| BR-05 | 사용자 정의 카테고리는 해당 사용자만 생성, 수정, 삭제할 수 있다. |
| BR-06 | 할일 목록은 카테고리, 종료예정일 기간, 완료 여부를 기준으로 필터링할 수 있다. |
| BR-07 | 사용자는 자신의 개인 정보(이름, 비밀번호 등)를 수정할 수 있다. |
